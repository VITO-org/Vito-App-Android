# HU-99: Banda leve pre-warning anclada al umbral efectivo (baseline HU-98)

> *Design document — Pluggable Middle Phase 09.B.*
> *Session: `2026-08-29_hu-99-motor-de-umbrales-dinamicos-segun-baseline-personal-front-portable-a-back` · Spec: `/Users/cristianvera21/Documents/proyecto-final/Vito-App-Android/.cortex/vault/specs/2026-08-29_hu-99-motor-de-umbrales-dinamicos-segun-baseline-personal-front-portable-a-back.md`*

## Architecture decision

Severidad 'leve' implementada como banda pre-warning relativa al umbral de advertencia efectivo (que ya deriva del baseline HU-98). No se necesita sigma/meadia en el detector: la banda se ancla al warning efectivo, que ya esta posicionado a media +/- 2*sigma del baseline. 'advertencia' cumple el rol de 'moderada' — se conserva el nombre para no romper alertas persistidas. Severity rank: INFO=0, leve=1, advertencia=2, critica=3. Dedup existente por rank funciona sin cambios. Zonas SpO2 (warning 90, banda 2): <85 critica, 85-87.99 advertencia, 88-89.99 leve, >=90 normal — las franjas existentes se desplazan 2 puntos: tests legacy de franja 88-90 se actualizan.

## Data model changes

- types.ts: AlertSeverity + 'leve'
- types.ts: Spo2Thresholds.leveBandPercent = 2 (default)
- types.ts: HrThresholds.leveBandBpm = 5 (default)
- types.ts: BpThresholds.leveBandMmhg = 5 (default)
- personalized.ts: PersonalizationConfig + 3 campos de banda leve; derive* los incluyen en umbrales personalizados

## API contracts

- AlertSeverity pasa a 'INFO' | 'leve' | 'advertencia' | 'critica' — se mantiene 'advertencia' (moderada) sin renombrar para no romper alertas previas en DB
- Spo2Thresholds.leveBandPercent (default 2): leve si warning - banda <= valor < warning
- HrThresholds.leveBandBpm (default 5): taqui leve si warning < bpm <= warning+banda; bradi leve si warning-banda <= bpm < warning
- BpThresholds.leveBandMmhg (default 5): analogo a HR por direccion
- PersonalizationConfig agrega spo2LeveBand/hlLeveBandBpm/bpLeveBandMmhg — derive*THRESHOLDS preservan la banda en umbrales personalizados

## Test plan

- Tests comparativos: paciente con baseline valido genera menos alertas (falsas) que con OMS estatico
- Tests comparativos: paciente sin baseline usa OMS (fallback identico a estatico)
- Tests por metrica: clasificacion leve/moderada/critica en las 3 fronteras
- Tests de regresion: 136 base + nuevos pasando
- Tests dedup: leve activa no recrea hasta escalar a advertencia

## Risks

- Tests legacy que verifican severidad exacta en franja de 2 puntos junto al warning deben actualizarse (cambio intencional)
- El nivel 'leve' genera mas alertas (aviso temprano) — mitigado por dedup por rango: una vez activa la leve, no se recrea hasta cruzar a advertencia/critica
- Backend Futuro: portable a Edge Function con los mismos tipos puros
