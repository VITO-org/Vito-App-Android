# HU-98: Cálculo de Baseline Personalizado por Paciente

> *Design document — Pluggable Middle Phase 09.B.*
> *Session: `2026-08-23_scrum-114-hu-98-calculo-de-baseline-personalizado-por-paciente` · Spec: `/Users/cristianvera21/Documents/proyecto-final/Vito-App-Android/.cortex/vault/specs/2026-08-23_scrum-114-hu-98-calculo-de-baseline-personalizado-por-paciente.md`*

## Architecture decision

Nueva tabla baseline_personalizado (una fila por usuario) con estadísticas por métrica (media, desviación estándar, P25, P75). Cálculo en PL/pgSQL server-side via función SECURITY DEFINER. Trigger: pg_cron nocturno + on-demand RPC. Fallback: umbrales estándar OMS cuando n < 30 muestras. Derivación de umbrales personalizados con guardarriles absolutos. Cache 1h en engine.ts.

## Data model changes

- Nueva tabla baseline_personalizado (schema.sql §9)
- Nueva interfaz BaselinePersonalizado en models.ts
- Nuevos tipos MetricStats, PersonalizedMetrics en personalized.ts
- Constantes PERSONALIZATION_DEFAULTS con guardarriles

## API contracts

- getBaselinePersonalizado(userId) → BaselinePersonalizado | null
- recalcularBaseline(userId) → void (RPC)
- recalcular_baselines_pendientes() → void (pg_cron)
- resolveEffectiveThresholds(userId) → {spo2, bp, hr} thresholds

## Test plan

- deriveSpo2Thresholds: clamps y valores exactos
- deriveHrThresholds: atleta sin falsa bradicardia, criticals en guardarriles
- BP derivación: paciente crónico relajado, jamás más sensible
- resolveEffectiveThresholds: mix métricas válidas + NULL → merge correcto
- Engine: baseline personalizado → alertas con umbral_origen tag
- Cache: dos evaluaciones dentro de TTL → un solo fetch
- SQL: semilla datos_reloj → stats match hand-computed
- SQL: 5 días → todos NULL, es_valido=false
- Idempotencia: doble run → misma fila
- RLS: usuario no lee ajeno, no llama recalcular_pendientes
- Tests existentes alerts.test.ts sin regression

## Risks

- pg_cron puede no estar disponible en Supabase free tier — fallback: Edge Function o trigger manual desde app
- Pacientes con datos muy irregulares pueden tener stats poco representativos — mitigado por ventana de 28 días y filtro sospechoso
- Derivación de umbrales requiere aprobación clínica — constantes están en un solo objeto configurable
